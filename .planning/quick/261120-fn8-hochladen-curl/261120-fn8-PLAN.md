# Quick 261120-fn8: curl-Ausweg für `ablegen()` (hochladen, ifc, oberflaechen)

Live UNA 20.11.2026: `plattform_abgleich.py hochladen` scheitert auf macOS (python.org-Python) mit
`URLError … CERTIFICATE_VERIFY_FAILED`. `herunterladen()` hat dafür schon einen curl-Ausweg, `ablegen()` nicht.
Live wurde stattdessen von Hand hochgeladen:
`curl -sS -X PUT -H "x-ms-blob-type: BlockBlob" -H "Content-Type: application/json" --data-binary @ergebnis.json <link>` → 201.

## Aufgabe 1 (Test zuerst)
- `ablegen(link, daten, typ)`: urllib wie bisher; bei `urllib.error.URLError`/`ssl.SSLError` mit
  „CERTIFICATE_VERIFY_FAILED“ im Text → Ausweg über curl, sonst Fehler weiterreichen (wie `herunterladen`).
- Ausweg: Daten in eine temporäre Datei (`tempfile.NamedTemporaryFile(delete=False)`, im `finally` löschen),
  `subprocess.run(["curl", "-sS", "--fail", "-X", "PUT", "-H", "x-ms-blob-type: BlockBlob", "-H", f"Content-Type: {typ}",
  "--data-binary", f"@{pfad}", "-o", "/dev/null", "-w", "%{http_code}", link], capture_output=True, timeout=3600)`
  — Argumentliste, nie Shell; Link vorher durch `_nur_https`. Erfolg nur bei Rückgabe 0 und http_code 200/201,
  sonst `Fehler` mit Code und stderr (gekürzt, ohne den Link mit Signatur auszugeben: Query-Teil abschneiden).
- Gemeinsamer Helfer für „ist Zertifikatsfehler“, den `herunterladen` und `ablegen` beide nutzen.
- Tests ohne Netz: `urllib.request.urlopen` per monkeypatch auf Zertifikatsfehler, `subprocess.run` gefälscht →
  (a) curl bekommt PUT, beide Header, `--data-binary @<datei>`, Link als letztes Argument, kein `shell=True`;
  temporäre Datei existiert danach nicht mehr; (b) http_code 403 → `Fehler`, Meldung ohne `sig=`;
  (c) anderer URLError (z. B. Verbindung abgelehnt) → wird nicht über curl wiederholt.
